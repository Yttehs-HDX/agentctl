# agentctl v0.2 delivery report

Written 2026-11-25. Everything below was measured on this machine: Herdr Core
0.1.18, OMP 19.1.0, Pi 1.5.2, Claude Code 2.1.327. Where something is inferred
rather than measured, it says so.

Highest priority was reliability. Several features below are narrower than the
brief because a wider version would have required claiming a guarantee the
harness cannot give.

## What works

### Workspace auto-detection (2.1)

`--workspace`, then `AGENTCTL_WORKSPACE`, then the workspace at the current
directory, then the nearest registered root above it. Every path is
canonicalized, so a symlink and its target share one workspace. Nested
workspaces resolve to the innermost. Discovery never creates a workspace, never
picks an unrelated one, and fails with `workspace_not_initialized` (exit 4) when
nothing matches. `init` with no arguments registers the current directory.
`rebind` is unchanged.

### Leader lease and fencing (2.2)

One row per workspace in `leader_leases`, so SQLite's write serialization is the
arbiter. Six concurrent claims produce exactly one winner. A lease carries
`leader_instance_id`, `leader_epoch`, `lease_token` and `expires_at`. Attach by
another instance is refused while the lease is live; `takeover` bumps the epoch
and invalidates every earlier token.

Fencing: once a lease exists, each mutating command must present its token.
Before any lease exists the workspace is unclaimed, so single-operator use of
v0.1 is untouched. A superseded instance gets `leader_conflict` instead of
acting. The daemon renews while it runs.

Stated plainly, in the docs and in the code: this is a coordination primitive
for one Unix user, not a security sandbox.

### Message registry (2.3)

The row is written before the text is sent, and `dispatching` is committed
before the transport call, so a crash inside that window is visible instead of
silent. States: `queued`, `dispatching`, `dispatched`, `acknowledged`, `running`,
`completed`, `failed`, `cancelled`, `delivery_unknown`. Legal moves live in one
table (`messaging/transitions.py`).

- Exact ACK: the message id travels inside the text, and the hook reads it back.
  An ACK proves *that* message arrived, not that the worker was idle.
- One message in flight per session (partial unique index); queued messages wait.
  Different workers run in parallel.
- Duplicate ACKs, duplicate completions and replayed hooks are no-ops.
- `retry` refuses `delivery_unknown`: the text may already be in the worker's
  context. A dispatch that never got an ACK becomes `delivery_unknown` after a
  window rather than hanging forever.
- Text with newlines, quotes, `$VAR`, `--flags` and Unicode arrives byte-intact
  (asserted in `test_messages.py`).

### Event bus, inbox and `agentctld` (2.4)

`hc events --json --label agentctl.workspace=<id>` streams a snapshot line, then
one JSON-RPC notification per fact change, with `seq` and heartbeats. The mapper
(`events/ingest.py`) is pure and dedupes on `(session, turn)`, so `status: done`
followed by a `turn` bump yields one `turn.completed`. Blocked, exit and
status-change are reported once per occurrence.

Events are append-only rows; Leader-relevant ones also get an inbox row with a
dedupe key. `agentctld` follows the stream, renews the lease, dispatches one
message per worker, drains the hook spool, and delivers or defers inbox items
with backoff. Every unit of work is a row in `outbox`/`inbox`, so a restart is
"still pending", not a replay of side effects. A fenced daemon stops dispatching.

`send` is asynchronous by default and returns a message id in about a second.
`--wait N` turns it into a barrier; `--sync` keeps the v0.1 behaviour.

### Harness integrations (2.5, 2.7)

Verified end to end against a real worker for each harness:

| Harness | Result |
| --- | --- |
| OMP 19.1.0 | `queued → dispatched → acknowledged → running → completed`, `turn.completed` in the inbox |
| Pi 1.5.2 | `queued → dispatched → acknowledged → completed`, `turn.completed` in the inbox |
| Claude 2.1.327 | `queued → dispatched → acknowledged → completed` after the trust prompt was answered, `turn.completed` in the inbox |

Three findings changed the design and are worth reading:

1. **`pi.exec` cannot spawn from an `input` handler.** It rejects with
   `ENOENT ... posix_spawn`. A hook that reported by running `agentctl` could
   therefore never acknowledge a message. Hooks now append one JSON line to
   `$AGENTCTL_HOME/spool/<agent>.jsonl` with `node:fs`, which works from every
   handler. Any CLI command or the daemon drains that file.
2. **An extension that declares no flag is loaded only after the first prompt**,
   so it misses exactly the message a Leader is waiting on. The generated hook
   registers a flag to force an eager load.
3. **`agent_settled` did not fire in the OMP TUI**; `agent_end` did, once per
   run, in both OMP and Pi. Completion now reports from `agent_end`.

Install writes only under `$AGENTCTL_HOME/integrations/<agent>/` and hands the
hook to the worker at launch (`-e <path>` for OMP and Pi, `--settings <fragment>`
for Claude). A user's own harness configuration is never read, edited or backed
up. Install is idempotent. `integrations list` marks a harness `verified` only
where its capabilities were measured here, and lists codex and opencode as
unsupported with the reason.

`doctor` checks the runtime, workspace, lease, daemon, each agent's version drift
and each installed hook in one pass.

### Leader skill (2.8)

`skills/agentctl-leader/SKILL.md`: workspace resolution, lease handling, worker
selection, async dispatch, event triage, treating worker output as untrusted
data, recovery order after a restart, duplicate-work avoidance and deliberate
cleanup.

## Architecture decisions and trade-offs

- **A lease row, not a lock file or pid.** A crashed Leader stops renewing and
  the row expires; nothing has to clean up. Cost: a Leader must renew, so a long
  unattended run needs the daemon or periodic heartbeats.
- **Fencing only starts once someone attaches.** This keeps v0.1 unbroken, but
  it means an unattended workspace has no protection until the first `attach`.
  `doctor` and `leader status` say so.
- **A marker inside the message text, not a transport id.** Herdr Core has no
  per-message id, so the id has to travel in-band. Cost: the worker sees the
  marker; the payload is unaffected and is asserted to arrive intact.
- **Hooks spool files, not RPC.** Measured necessity: subprocesses do not work
  from `input`. Cost: ingest is polled by the CLI and the daemon rather than
  pushed, so an event can sit for up to one tick (1 s with the daemon, or until
  the next CLI call without it).
- **Agent-owned hook assets.** A user's harness config is never touched. Cost:
  the hook is only present in sessions agentctl launched, which is the only case
  that matters.
- **`agent_end`, not `agent_settled`.** `agent_end` is the event both harnesses
  actually emit in a TUI. Cost: it fires before retry/compaction repair, so a
  rare post-`agent_end` continuation reports a turn that then continues.

## Known issues

1. **A send that lands mid-turn can be swallowed.** Measured: text typed while
   the worker is working stays in its composer. Dispatch now refuses a non-idle
   worker (`_Refused`, message stays `queued`), and the daemon retries when the
   worker is idle, but a race remains: a worker that reports `idle` and then
   starts its own continuation can still eat the text. `delivery_unknown` after
   the ACK window is the honest outcome, and `messages get` says so.
2. **Spool ingest is polled.** Without the daemon, hook facts appear on the next
   CLI call. With it, within a tick.
3. **Claude has no turn-start event.** The ACK stands in for "started".
4. **Codex and OpenCode are unsupported.** No verified hook; codex emits no
   status record for the runtime fallback either.
5. **The daemon follows only one workspace.** Multi-workspace supervision means
   one daemon per workspace, started separately.
6. **`daemon start` is detached, not socket-supervised.** The CLI reads
   `daemon.json` and checks the pid. A UDP/TCP-free supervisor was out of scope;
   the socket path is reserved in the state file.
7. **Vendored check only covers the hooks we ship.** A user-authored extension
   can still break its own `input` handler.

## Not done

- No `agentctld` socket protocol. The CLI and daemon coordinate through SQLite,
  which is the durable state either way; a socket would only shorten wakeups.
- No automatic `prune` of spool files from a harness that is uninstalled.
- No lease auto-renewal from a Leader that runs without the daemon (the skill
  tells it to heartbeat).
- Real end-to-end for codex and opencode: out of scope by measurement.

## How this was verified

- `pytest`: 241 tests, all hermetic except `test_hook_source`, which loads the
  generated hook with the real `omp` binary because only that parser matters.
- Real Herdr Core in a scratch core (`HC_SESSION=aclab`, isolated `XDG_*`), so
  no live terminal of the user's was touched.
- Real workers for OMP, Pi and Claude, each driven through
  `create → send → ACK → completion → inbox`.

## Next steps worth taking

1. A `--state dispatching` sweep interval configurable per agent, so a slow
   harness is not declared unknown prematurely.
2. A daemon socket for immediate wakeups, once polling proves to be the
   bottleneck.
3. A codex adapter if a hook appears; until then its `delivery_unknown` is the
   honest state.
4. Multi-workspace daemon supervision if Leaders start spanning projects.
