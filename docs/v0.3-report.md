# agentctl v0.3 refactor report

2026-11-25. The question this refactor answered: *is this code wrapping Herdr, or
re-implementing it?* Anything in the second category was removed.

## What was removed

| Removed | Lines | Why it should not exist |
| --- | --- | --- |
| `messaging/service.py` | 617 | A message queue, state machine, retry policy and ACK protocol. Herdr sends; the harness owns its own input queue. |
| `messaging/transitions.py` | 77 | The state machine above, in isolation. |
| `daemon/service.py` | 505 | `agentctld`: a supervised process following an event stream to dispatch messages. Herdr already runs the terminals. |
| `integrations/registry.py` | 472 | Per-harness hook installation and a capability registry. |
| `integrations/hooks.py` | 300 | Hook entry points that wrote the message registry. |
| `integrations/omp_hook.py` | 158 | A TS extension injected into the Worker. |
| `integrations/claude_hook.py` | 31 | A `Stop`-hook script. |
| `integrations/base.py` | 79 | The adapter interface neither of the above earned. |
| `events/ingest.py` | 184 | A second mapper from Herdr facts to "agentctl events". Herdr already emits turn and status facts. |
| `events/bus.py` | 174 | A persistent event log with dedupe and an inbox. |
| `leader/service.py` (lease) | 284 → 223 | Expiring lease, epoch, fencing token. Replaced by a binding; see below. |
| `spool.py` | 160 | A file transport invented to work around `pi.exec` inside a hook. |
| `diagnostics.py` | 134 | `doctor`, which mostly checked the things above. |
| `clock.py` (most) | 47 → 12 | Timestamp helpers only the deleted modules used. |

CLI: `messages`, `events`, `inbox`, `daemon`, `integrations`, `doctor` and the
hidden `hook` group are gone. `cli.py` went from 1964 to 1154 lines.

Schema version 4 drops `messages`, `events`, `inbox`, `outbox`,
`consumer_offsets`, `integrations` and `leader_leases`. Workspaces and sessions
migrate in place, so an upgraded registry keeps its identity and its Worker list.

## What was kept

- Workspace identity: canonical path, stable `ws_` / `leader_` ids, `init`,
  `rebind`, `info`, and CWD auto-detection (flag > env > cwd > nearest parent).
- Session lifecycle: `create`, `delete`, `list`, `status`, `recover`, `prune`,
  git worktrees, agent selection with a global default, `keys`, `interrupt`,
  `read`, `wait`.
- The agent catalog as **declarative** data: launch argv and resume flags per
  agent, not adapter code.
- Native session ids and relaunch-on-recovery for agents whose catalog entry
  says they are resumable.
- `--json` on every command, stable error envelope, exit codes.

## Delegated to Herdr

Verified against hc 0.1.18 in a scratch core:

| Capability | Herdr interface | Measured |
| --- | --- | --- |
| Worker survives the Leader | `--parent` + `--outlive-parent` | `parent=t1`, `die_with_parent=false`; Workers still `live` after `hc kill` of the Leader |
| Parent/child relation | `--parent` | children listed under the Leader's terminal |
| Native child notes | typed into an idle parent | `<hc from="t6 work3" …>` observed in the parent's screen |
| Delivery | `hc send` | verbatim text, one argv element |
| Blocked-agent guard | `hc send` refusal, `--if idle`, exit 9/10 | `status_mismatch` before anything is typed |
| Turn started or not | `hc send --wait` → `started` | `started:false` for a booting agent |
| Turn ended | `hc wait --children` → `reason: "status"` | returned with `turn` bumped for a child that reported `working → done` and sent nothing |
| Multi-worker barrier | `hc wait --children any\|all` | `reason:"timeout"` while a child works; `reason:"status"` when it stops |
| Status words | OSC 7501 `state=…:app=…` | `working → done`, `turn` 0 → 1 |
| Terminal liveness | `hc get` `state` | `finished` after `hc kill` |

## Still owned by agentctl, and why

- **Workspace identity.** Herdr has terminals and labels, not a project identity
  that survives a directory move.
- **Leader binding.** Herdr has no notion of "the Leader of this project". A row
  pointing at a terminal is the minimum that lets a restart find the pool.
- **Worker names and metadata.** Herdr has an address and a name; a Leader needs
  `researcher` → agent, cwd, worktree, native session id.
- **`--cwd` policy and worktrees.** Scoping and git hygiene are application
  decisions, not runtime ones.

The Leader binding deserves its own note. v0.2 used an expiring lease with epoch
fencing. That was a supervisor's job: the failure modes were renewals, epochs and
"who holds it now", and none of it produced a guarantee an OS boundary could
back. The replacement is one row (`workspace → terminal, native_session_id`) plus
a rule: a terminal labelled `agentctl.role=worker` can never be adopted as the
Leader. Staleness is answered by asking Herdr whether that terminal is live,
which is the only fact that matters.

## Verification

- 166 tests pass (`pytest`), hermetic against a fake `hc` except the real-Herdr
  scenario below.
- Real Herdr, scratch core (`HC_SESSION=hv3`-`hv5`), scripted harness reporting
  OSC 7501:
  1. Workspace created by CWD; two Workers created with a first task.
  2. Both Workers appear as children of the Leader's terminal.
  3. Both start and finish a turn in parallel (`turn 1` each).
  4. The Leader's terminal is killed; both Workers stay `live`.
  5. `leader status` reports `live: false` from Herdr's terminal state.
  6. A new Leader attaches with `--takeover`; the same Workers are listed.
  7. A Worker created after the takeover is parented to the new Leader; the old
     Workers are still alive.
  8. `wait --all` is `hc wait --children all`.

One bug this found: `hc` refuses a name shaped like a terminal address (`t7`),
which agentctl was passing through as a raw runtime error. `create` now rejects
such names with a hint.

## Known upstream limits

1. **A child's quiet turn end does not wake an idle parent.** Herdr types notes
   for blocked, error and exit only. Issue
   [#176](https://github.com/herdrdev/herdr-core/issues/176) requests the turn
   end; [PR #177](https://github.com/herdrdev/herdr-core/pull/177) is open and
   not merged on 0.1.18. A Leader learns about it by calling `wait --any`.
   agentctl deliberately does **not** add a hook or a message table to hide this.
2. `hc wait --children` needs the parent's terminal. An outside Leader must have
   attached one; with no binding the wait sees no children.
3. Herdr's `notes = false` config suppresses native notes entirely; agentctl does
   not override a user's Herdr configuration.
4. Worker survival depends on `--outlive-parent`; if a future Herdr changes that
   flag's meaning, survival becomes Herdr's `keep` recovery instead.

## What was deliberately not built

- No `agentctld`, no sockets, no event forwarding process.
- No Worker hooks or harness-specific lifecycle plugins.
- No message ids, ACKs, retries or consumer offsets.
- No `doctor`: `setup` already reports what it checked, and the remaining checks
  are Herdr's own `hc server status`.

The test for any future addition: if the code is re-implementing Herdr rather
than making it easier to use, it should not be in agentctl.
